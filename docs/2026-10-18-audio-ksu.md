## 一、asp_codec codecless 驱动（音频）

华为开源 drop 里 `sound/soc/codecs/vendor/asp_codec/`、`asp_codec_ana/`、`au_pa/`
三个目录**只剩 Kconfig + Makefile**，源码被剥离。本改动从原厂 `stock163.elf`
（0.163 内核，带完整符号表）反向提取数据表并重建驱动：

| 文件 | 内容 |
|---|---|
| `asp_widgets_gen.h` | 165 个 DAPM widget + 222 条 route |
| `asp_events_gen.h` | 52 组 DAPM 电源事件寄存器序列（原 40 组 + 12 个 CIC/DMIC 开关） |
| `asp_reg_map.h` | 361 个控件的 `(reg, shift, mask)` 映射 |
| `asp_tables_gen.h` | 137 controls / 87 widgets / 46 routes 的早期提取结果 |
| `codecless_virt_controls.h` | 361 int + 4 enum 虚拟控件，enum 已接真实寄存器 |
| `asp_codec_codecless.c` | 驱动主体（见下） |
| `asp_routes_gen.h` | 路由表（platforms 目录） |
| `da_combine_machine.c` | codecless 声卡定义 |

`asp_codec_codecless.c` 提供：

- **时钟/供电**：`regulator "asp"` → `clk_asp_subsys` → `clk_asp_codec`，实测 49.152 MHz
- **寄存器窗口**：codec `0xFA552000`（0x00–0x28C）、ASP cfg `0xFA54E000`、
  ASP DMAC `0xFA54B000`
- **初始化序列**：cfg `0x00/0x04/0x0C` 写入，codec `0x94…0x180 |= 0x400`，
  `0x20[15:13]←2`，`0x14 |= 0x40000000`
- **DAPM 事件**：把 `asp_events_gen.h` 的 `(reg,mask)` 序列挂到 widget 的
  `PRE_PMU` / `POST_PMD`
- **DMA 端口配置**：`0x200–0x21C` 按原厂 `codecless_dma_config` 写入
- **`/proc` 调试接口**（本次排障的主力工具）：
  - `/proc/moli_audio` —— 实时寄存器 dump + 控件写入日志
  - `/proc/moli_ctl` —— 运行时命令：`r/w/u`（codec）、`cr/cw/cu`（cfg）、
    `dm/dmd`（ASP DMAC）、`pm <phys> <len>`（读 DSP 保留 DDR）、
    `pcm`（ALSA runtime）、`seq on|off <widget>`（手动应用事件序列）、
    `dw/dr`（da_combine 寄存器）、`setctl`、`i2c`、`syncall`
  - `/proc/moli_ctls` —— 597 个控件的完整枚举
- **MOLI_GUARD**：DSP 异常会清零 codec 块，下次 TRIGGER_START 时自动重初始化

### 已确认的硬件事实

- HAL → DDR → DSP 链路通：`hw_ptr` 按实时速率前进，PCM 缓冲有真实音频样点
- 播放链 15 个控件 HAL 全部正确写入并落地（`0x004=0xC0`、`0x00C=0x1E0040`、
  `0x13C=0x14CC00`、`0x0B4=0xF30000`）
- 智能功放 `smartpakit_i2c` 驱动完整、已绑定、被 HAL 上电（`POWER_ON_L/R succ`），
  播放时写入 25 个寄存器
- `0x00C` / `0x0C8` / `0x010` 是 DSP 独占控制面，AP 侧只能读不能写
  （5 种写法/时机全部掉 fastboot，已停止该方向）

### 仍未解决

外放与麦克风**仍无声**。链路配置已与原厂逐条比对一致，缺的是
`asp_codec` path 模块注册的**运行时 ops 函数指针**（`play_config_power_event`
里 `ldr x19, [x8, #2232]` 取到的那个，为 NULL 时直接走错误分支）。
该模块在 drop 里被剥离，二进制里也没有可反汇编的实现。

## 二、KernelSU 授权持久化（`patches/kernelsu-moli-fixes.patch`）

症状：管理器里给 App 授权 root，**重启后授权丢失 / 管理器显示「未安装」**。

### 根因（全部有 dmesg 实证）

```
on_post_fs_data!
MoLi allowlist: primary open failed -2, trying fallback
MoLi allowlist: BOTH paths failed -2
...
save_allow_list create file failed: -126          ← -ENOKEY
```

1. **保存失败**：`override_creds(ksu_cred)` 把 **session keyring** 一并换掉，
   而 FBE 的解密密钥挂在 keyring 上，所以内核写 FBE 加密的 `/data` 返回 `-ENOKEY`。
2. **加载过早**：`on_post_fs_data()` 在 `/data` 解密前后读 allowlist，
   失败后不再重载。
3. **管理器未加冕**：开机早期校验管理器 APK 签名同样 `-ENOKEY`，`is_manager: 0`。

### 修复（3 个文件）

**`kernel/policy/allowlist.c`**

```c
/* 克隆调用者 cred，只把 uid/gid/caps 提到 root，保留 session keyring */
static const struct cred *moli_fbe_creds(void)
{
    struct cred *new = prepare_creds();
    if (!new) return NULL;
    new->uid = new->euid = new->suid = new->fsuid = GLOBAL_ROOT_UID;
    new->gid = new->egid = new->sgid = new->fsgid = GLOBAL_ROOT_GID;
    new->cap_inheritable = ksu_cred->cap_inheritable;
    new->cap_permitted   = ksu_cred->cap_permitted;
    new->cap_effective   = ksu_cred->cap_effective;
    new->cap_bset        = ksu_cred->cap_bset;
    new->cap_ambient     = ksu_cred->cap_ambient;
    return new;
}
```

- 保存走 `override_creds(moli_fbe_creds())`，主路径 `/data/adb/ksu/.allowlist`，
  失败回退 `/metadata/ksu/.allowlist`
- 加载回退条件从「仅 `-ENOENT`」放宽到「任何错误都试回退」
- 新增 `allowlist_loaded_ok` + `ksu_allowlist_try_reload()`（8 次上限），
  在 `__ksu_is_allow_uid()` 开头补读
- 关键路径日志改 `pr_err` 并打印 `allow=` 值

**`kernel/runtime/boot_event.c`**

- `on_boot_completed()` 里补一次 `ksu_load_allow_list()`
- 新增管理器加冕延时重试（`schedule_delayed_work`，3 秒间隔，最多 10 次）

**`kernel/hook/setuid_hook.c`**

- 不再对**管理器**调 `disable_seccomp()` —— 管理器读自己的
  `/proc/self/status` 判断 seccomp 状态，被剥掉后会永远显示「未启用」
- `disable_seccomp()` 限定到 `is_appuid(ruid)`，不再波及 root / 系统进程

### 验证结果

```
模块 moli_ksu_persist / moli_crown 全部 disable（完全不依赖模块）

Crowning manager: uid=10214                      ← 自动加冕成功
MoLi crown: manager already valid (try 1)

MoLi allowlist: file opened ok
MoLi allowlist: version=4

关掉 adb_root 后：
  adb shell id : uid=2000(shell)
  su -c id     : uid=0(root) context=u:r:ksu:s0   ← 授权生效

com.sukisu.ultra 的 Seccomp = 2（之前是 0）
```

## 三、如何应用

### asp_codec 驱动

直接把 `source/asp_codec_codecless/` 下的文件放到
`sound/soc/codecs/vendor/asp_codec_codecless/`，
`source/asp_routes_gen.h` 放到 `sound/soc/platforms/`，
`source/da_combine_machine.c` 覆盖同路径文件。

需要内核配置（defconfig）：

```
CONFIG_SND_SOC_ASP_CODEC_CODECLESS=y
CONFIG_SND_SOC_DA_COMBINE_V5=y
CONFIG_HIFI_DSP_ONE_TRACK=y
CONFIG_CODEC_DSP_MISC=y
CONFIG_HIFI_MAILBOX=y
```

### KernelSU

```bash
cd KernelSU
git am ../patches/kernelsu-moli-fixes.patch
```

## 五、未验证项（诚实清单）

1. **外放无声** —— 链路配置与原厂一致，但无法确认是否出声；
   缺 `asp_codec` path 模块的运行时 ops

   这是本 ROM 自身行为（改动前即为 0），未做处理
